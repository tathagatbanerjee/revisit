# Contributing

Start with README.md, docs/README.md and AGENTS.md. The first milestone is a
qualified static upload-to-result workflow, before new quality experiments or
new-video dynamic fitting. Current paid allocation is disabled.

Use app/ for the local viewer/service, core-pipeline/ for reconstruction code,
docs/ for durable evidence and ignored working/ for scratch work. Keep each failed
attempt and its original settings; never relabel synthetic geometry as a captured
reconstruction or source-view scores as independent-view accuracy.

For a result card, lead with question, outcome and lesson. Then include IDs,
parent/control relationships, source interval and frame clocks, settings,
measurements, failed gates, visual limitations, license/provenance and evidence
availability. Historical records can be indexed without redistributing their
restricted images/models. Do not replace failed records with a passing revision.

Run JavaScript/tests, documentation/syntax and publication audits before pushing.
CI creates no paid resources. Live cloud tests need an explicit bounded allocation
and must verify cleanup. Preserve required upstream notices and keep credentials,
footage, checkpoints, generated screenshots and execution state out of Git.

An independent new-user rehearsal is required before quick-setup claims: record
platform, prerequisites, setup/first-view timings and every manual intervention.
Report missing evidence rather than inventing a successful verification.
